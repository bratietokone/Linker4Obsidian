# Linker

**Язык документации:** [English](README.md) | [Русский](README.ru.md) | [Español](README.es.md) | [简体中文](README.zh-CN.md)

Плагин для настольной версии [Obsidian](https://obsidian.md/), который автоматически встраивает вложения, но оставляет ссылки на Markdown-заметки обычными Wiki-ссылками. Также преобразует отдельные YouTube URL во встроенный видеоплеер.

**Версия:** 0.5.1 · **Статус:** опубликован в каталоге сторонних плагинов Obsidian · **Требования:** Obsidian 1.8.7 или новее (Windows, macOS, Linux).

## Возможности

- Markdown-заметки остаются ссылками `[[note.md]]`; изображения, PDF, аудио и видео автоматически получают формат встраивания `![[file.ext]]` по настраиваемым правилам.
- Обработка новых Wiki-ссылок при наборе, вставке и выборе через встроенное автодополнение `[[`.
- Встраивание YouTube (`youtube.com`, `youtu.be`, Shorts, `/live/`) в виде `![](URL)` при вставке в подходящее место или при преобразовании существующих заметок.
- Предварительный просмотр перед изменением ссылок в текущей заметке или во всём хранилище.
- Выбор языка интерфейса: **Автоматически (язык Obsidian)**, **English**, **Русский**, **Español** и **简体中文**. Настройки, диалоги и уведомления переводятся сразу; имена команд — после перезагрузки плагина.
- Не требуется аккаунт, сервер или отправка содержимого заметок во внешние сервисы.

- **Внешние файлы и папки:** создание Markdown-ссылок `file:///` и Wiki-ссылок `[[external:...]]` на объекты за пределами хранилища без копирования файлов.

> **Переход с Linker4Obsidian 0.4.0 и более ранних версий:** ID изменился с `linker4obsidian` на `linker`. Отключите старый плагин, установите Linker 0.5.0 или новее в `.obsidian/plugins/linker/` и при необходимости скопируйте `data.json` для сохранения настроек. Проверьте новую установку перед удалением старой папки. Старые релизы используют другой ID.

**Доступ к файловой системе и конфиденциальность:** функция внешних ссылок доступна только в настольной версии. При выборе или открытии ссылки плагин проверяет метаданные указанного локального файла или каталога через Node.js, затем использует Electron для открытия либо показа объекта в файловом менеджере. Доступ за пределы хранилища нужен именно для этой функции. Содержимое внешних файлов не читается и не передаётся в сеть; содержимое заметок и телеметрия также не отправляются.

## Установка в Windows, macOS и Linux

> Перед массовым преобразованием ссылок и испытанием новых сборок сделайте резервную копию хранилища.

### Через Obsidian (рекомендуется)

1. Откройте **Настройки → Сторонние плагины (Community plugins) → Обзор (Browse)**.
2. Найдите **Linker** (автор **bratietokone**) или откройте [страницу Linker в каталоге](https://obsidian.md/plugins?id=linker).
3. Нажмите **Установить**, затем **Включить**. В **Настройки → Linker** выберите язык и правила обработки ссылок.

Это основной способ установки и получения опубликованных обновлений на Windows, macOS и Linux. **Скачивать файлы вручную не требуется.**

### Ручная установка (для тестирования и особых случаев)

Если нужна конкретная версия GitHub или тестовая сборка из ветки разработки:

1. Получите проверенные `main.js` и `manifest.json` из [GitHub Releases](https://github.com/bratietokone/Linker4Obsidian/releases) либо из артефакта GitHub Actions нужной ветки. В релизе **0.5.1 доступны два отдельных файла, а не ZIP-архив**. В более ранних релизах ZIP мог присутствовать.
2. Найдите каталог нужного **хранилища Obsidian**, а не папку установленной программы. Создайте внутри `.obsidian/plugins/linker/`.
3. Поместите туда `main.js` и `manifest.json`:

   ```text
   YourVault/
   └── .obsidian/
       └── plugins/
           └── linker/
               ├── manifest.json
               └── main.js
   ```

4. Перезапустите Obsidian или перезагрузите сторонние плагины, затем включите **Linker** в настройках.

Перед установкой тестовой сборки поверх рабочей сохраните резервную копию хранилища и настроек `data.json`. Решение о релизе принимается только после локальных испытаний.

### Где находится папка плагинов?

| Система | Пример пути | Как показать скрытые каталоги |
| --- | --- | --- |
| Windows | `C:\Users\<user>\Documents\MyVault\.obsidian\plugins\linker\` | Проводник → **Вид → Показать → Скрытые элементы** (названия зависят от версии Windows). |
| macOS | `/Users/<user>/Documents/MyVault/.obsidian/plugins/linker/` | Finder: **Cmd+Shift+.** |
| Linux | `/home/<user>/Documents/MyVault/.obsidian/plugins/linker/` | В большинстве файловых менеджеров: **Ctrl+H**. |

Это **примеры**, а не обязательные места хранения. Vault может находиться где угодно: на другом диске, в синхронизируемой папке и т. д. Папка `.obsidian` находится именно **внутри хранилища**. Не создавайте второй вложенный каталог `linker/linker/`.

## Выбор языка интерфейса

Откройте **Настройки → Linker → Язык интерфейса**:

| Вариант | Как работает |
| --- | --- |
| Автоматически (по умолчанию) | Следует поддерживаемому языку интерфейса Obsidian; для неподдерживаемых языков используется английский. |
| English | Английский независимо от настроек Obsidian. |
| Русский | Русский независимо от настроек Obsidian. |
| Español | Испанский независимо от настроек Obsidian. |
| 简体中文 | Упрощённый китайский независимо от настроек Obsidian. |

Настройки переключаются сразу, а уведомления и диалоги преобразования отображаются на выбранном языке. **Перезагрузите плагин**, чтобы названия команд в палитре тоже обновились. Все переводы интерфейса находятся в отдельных проверяемых TypeScript-модулях `src/locales/`.

## Правила по умолчанию

| Содержимое | Результат |
| --- | --- |
| Заметки Markdown (`.md`, `.markdown`) | `[[Notes/My note.md]]` |
| Изображения (`.png`, `.jpg`, `.webp`, `.svg` и др.) | `![[photo.webp]]` |
| Документы PDF | `![[document.pdf]]` |
| Локальное видео (`.mp4`, `.webm` и др.) | `![[video.mp4]]` |
| Локальное аудио (`.mp3`, `.flac` и др.) | `![[audio.mp3]]` |
| Неизвестные расширения | `[[archive.zip]]` |
| Отдельная ссылка на видео YouTube | `![](https://www.youtube.com/watch?v=VIDEO_ID)` |
| Другие веб-сайты | Обычная ссылка |

Категории и дополнительные расширения можно настроить. Правило **«Всегда оставлять ссылкой»** приоритетнее **«Всегда встраивать»**. Показ встроенного файла зависит от поддержки его формата в Obsidian.

## Внешние файлы и папки

В **Настройки → Linker → Внешние файлы и папки** добавлена отдельная страница. Можно включить обработку внешних ссылок и выбрать формат создаваемых ссылок — Markdown или Wiki. При этом открытие поддерживает оба формата независимо от настройки.

```markdown
[Проекты](<file:///home/user/Projects/>)
[Отчёт](<file:///home/user/Documents/report.pdf>)

[[external:/home/user/Projects/|Проекты]]
[[external:/home/user/Documents/report.pdf|Отчёт]]
```

Для вставки используйте команды **Вставить ссылку на внешний файл** и **Вставить ссылку на внешнюю папку**. Там можно выбрать объект через системный диалог (если доступен) либо вручную указать абсолютный путь. Название ссылки можно отредактировать.

Нажатие в режиме чтения или Live Preview открывает файл приложением по умолчанию, а папку — файловым менеджером. В настройках можно выбрать вместо открытия показ объекта в файловом менеджере. Исполняемые файлы только показываются, но не запускаются. Отсутствующие файлы и некорректные пути вызывают уведомление. Сетевые файловые URI и другие схемы не поддерживаются.

**Важно:** внешние файлы не встраиваются и не копируются в хранилище. Прежняя обработка вложений не изменяется.

## Использование

- **Новые ссылки:** введите Wiki-ссылку или выберите файл через автодополнение `[[` — плагин применит правило типа файла.
- **Перетаскивание и вставка файлов:** если Obsidian создаёт Wiki-ссылку, плагин нормализует её. За копирование файлов в хранилище отвечает сам Obsidian.
- **YouTube:** вставьте URL ролика в подходящую строку. URL внутри обычного предложения не преобразуется автоматически, чтобы не изменять ваш текст без необходимости.
- **Существующие заметки:** откройте палитру команд (`Ctrl+P` / `Cmd+P`) и выберите **Linker: Предпросмотр и преобразование ссылок в текущей заметке** или **Linker: Предпросмотр и преобразование ссылок во всём хранилище**. Просмотрите изменения и подтвердите их.

Плагин сохраняет уже созданные `![[...]]`, не переписывает огороженные блоки кода, YAML frontmatter, встроенный код и строки HTML-комментариев. Массовое преобразование требует подтверждения. **Перед ним сделайте резервную копию.**

## Ограничения

- Внешние пути должны быть абсолютными, зависят от устройства и могут быть недоступны из песочницы (например, Flatpak).
- Версия предназначена **только для настольного Obsidian**, не для мобильного приложения.
- Встраиваются поддерживаемые URL отдельных YouTube-видео; ссылки только на плейлист и другие сайты остаются обычными ссылками. Плагин не обходит запреты сайтов на iframe.
- Обычные Markdown-ссылки на локальные файлы `[file](image.png)` не преобразуются в Wiki-встраивания.
- Автоматически обрабатываются новые ссылки; для старых используйте команды преобразования.
- На создание ссылок могут влиять другие плагины и версии редактора Obsidian. Ошибки можно описывать в GitHub Issues.

## Разработка

Требуются Node.js и npm. Исходный код находится в `src/`, переводы — в `src/locales/`, `manifest.json` находится в корне репозитория, а `main.js` генерируется командой `npm run build` и не сохраняется в Git.

```bash
npm ci
npm run validate
npm run typecheck
npm run lint
npm run build
npm test
```

GitHub Actions запускает эти проверки при обновлениях и pull request. Плагин использует TypeScript и API редактора Obsidian, не требует сторонних библиотек во время работы и не отправляет сетевые запросы.

## Порядок разработки и публикации

**Текущая стабильная версия — 0.5.1.** Планируемая функциональность не считается реализованной и не публикуется автоматически.

1. **Перед каждым этапом подробно обсуждаем реализацию:** объём изменений, риски, критерии готовности и регрессионные сценарии.
2. Разрабатываем в **отдельной ветке GitHub и Pull Request**, не меняя стабильный релиз. Выполняем `npm ci`, `npm run validate`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm test`. CI дополнительно проверяет воспроизводимость сборки и предоставляет установочный тестовый артефакт.
3. Пользователь **локально тестирует сборку и функциональность в настольном Obsidian**, при необходимости выполняет самостоятельную сборку из исходников. Проверяем прежние Wiki-ссылки, вложения, YouTube и настройки. По замечаниям исправляем и повторяем испытания.
4. **Только после отдельного решения о публикации** обновляем версии в `manifest.json` и `package.json` до согласованного `X.Y.Z` и готовим записи CHANGELOG на поддерживаемых языках. Изменение версии манифеста в `main` автоматически запускает выпуск, поэтому до одобрения релиза версию не повышаем.
5. [GitHub Actions — Publish Linker release](https://github.com/bratietokone/Linker4Obsidian/actions/workflows/release.yml) проверяет код, собирает и аттестует артефакты, затем публикует GitHub Release с тегом `X.Y.Z` (без `v`) и файлами `main.js` и `manifest.json`. Собранный `main.js` в Git не сохраняется. Неуспешную публикацию можно повторить после исправлений; опубликованные версии не перезаписываются.

**Прохождение CI само по себе не разрешает релиз.** Не публикуем тестовые ветки и не переходим к следующему этапу без обсуждения и проверки.

- **Возможная очистка позже:** после отдельного обсуждения и локального тестирования — выборочное перемещение подтверждённых файлов в корзину. Автоматическое и безвозвратное удаление не планируются.
